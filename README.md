# Cofmart

Два самостоятельных интерфейса заказа кофе: Telegram-бот на aiogram и Telegram Mini App на React. Оба используют **один набор асинхронных Python-сервисов и одну PostgreSQL**. Mini App дополняет бота; все действия доступны через Telegram-кнопки.

## Архитектура

```text
Telegram → aiogram ────────┐
                          ├→ app/services → SQLAlchemy → PostgreSQL
Telegram Mini App → FastAPI┘
```

| Каталог | Ответственность |
| --- | --- |
| `app/bot` | Telegram-сообщения, callback, кнопки, состояние диалога |
| `app/api` | HTTP, проверка Telegram initData, схемы запросов и ответов |
| `app/web.py` | Локальный запуск: статический Mini App и API под `/api` на одном адресе |
| `app/ordering` | Общие правила полного бота из `main`: заказ, резервы, роли, избранное |
| `app/db/order_store.py` | Транзакционная граница общих правил, PostgreSQL advisory lock |
| `app/services` | Совместимость с ранними данными и историей |
| `app/db` | Общие SQLAlchemy-модели, фабрика async-сессий, начальные данные, CLI |
| `migrations` | Единая история Alembic для обоих Python-приложений |
| `frontend` | React + TypeScript + Vite; обращается только к API |
| `tests` | Авторизация, бот, API, транзакции и конкурентное бронирование |

Бот вызывает сервисы непосредственно и не требует запущенного FastAPI. API не требует работающего процесса бота: для проверки подписи ему нужен токен из `API_BOT`. Frontend можно размещать на любом хостинге статических файлов. Миграции выполняются отдельно от запуска приложений. Локальный launcher применяет их перед запуском.

## Локальный запуск на Windows: Mini App внутри Telegram

Docker не нужен. В подготовленном окружении запустите из корня проекта:

```powershell
.\start-local.cmd
```

Можно дважды нажать `start-local.cmd` в Проводнике. Оставьте открывшееся окно работающим.

Launcher поднимает локальную PostgreSQL при необходимости, применяет миграции, загружает каталог и создаёт пример слотов для кофеен, у которых ещё нет доступного времени. Затем собирает frontend, запускает локальный сервер и временный HTTPS-туннель localhost.run через OpenSSH. Компоненты выполняются на компьютере; PostgreSQL слушает только localhost. Через туннель доступны собранная страница и защищённый API; dev-сервер Vite не публикуется.

В Telegram автоматически настраивается кнопка меню **«Заказать кофе»** с типом `web_app`. Откройте бота по ссылке, которую напечатает launcher, отправьте `/start` и нажмите **«Открыть Mini App»** либо кнопку меню. Интерфейс откроется внутри Telegram. Для авторизации используется настоящий Telegram initData с серверной проверкой; входа от тестового пользователя нет.

Туннель нужен, чтобы Telegram на телефоне мог обратиться к приложению на компьютере по HTTPS. Аккаунт сервиса туннелей и публикация репозитория не нужны. Временный адрес меняется при каждом запуске, кнопка бота обновляется автоматически. После остановки компьютера или launcher адрес перестаёт работать. Launcher проверяет туннель каждые 10 секунд, восстанавливает соединение после сбоев и обновляет кнопку при смене адреса. Открытую Mini App со старым адресом нужно закрыть и открыть через меню бота заново. Старые кнопки в истории сообщений обновляются через новый `/start`. [Документация localhost.run](https://localhost.run/docs/).

Не запускайте `main.py` из IDE одновременно с `start-local.cmd`: launcher уже запускает бота. Межпроцессная блокировка по ID бота отклоняет второй локальный запуск, включая запуск из другой копии репозитория под тем же пользователем. При остановке launcher завершается всё дерево дочерних процессов Python; восстановление туннеля не перезапускает polling бота.

Остановка из другого терминала:

```powershell
.\start-local.cmd --stop
```

Также можно нажать Ctrl+C в окне launcher. Данные остаются в `.local/postgres`. Логи находятся в `.local/`, текущий HTTPS-адрес — в `.local/mini-app-url.txt`. Не удаляйте `.local/postgres`, если нужны сохранённые заказы. Вручную открытый локальный адрес без Telegram не авторизует пользователя — используйте кнопку бота.

Для нового окружения сначала установите зависимости Python и frontend, задайте `API_BOT` и локальный `DATABASE_URL` в `.env`. Укажите `COFMART_POSTGRES_BIN` — путь к `bin` установленной PostgreSQL — либо используйте уже подготовленный переносимый runtime `.local/postgres-runtime`. Node.js должен быть доступен в PATH; в текущем окружении также поддерживается установленный runtime Codex. Нужен стандартный компонент Windows OpenSSH Client. Для туннеля используется отдельный файл известных SSH-серверов `.local/tunnel-known-hosts`: ключ запоминается при первом соединении, изменённый ключ отклоняется. Пользовательские SSH-ключи не отправляются. Если локальная PostgreSQL уже работает, launcher использует её с реквизитами `DATABASE_URL`.

`main.py`, `app/handlers/student.py` и `app/keyboards.py` сохраняют совместимые точки импорта. Форматы старых кнопок `cafe:<id>` и `drink:<cafe_id>:<code>` сохранены. Построители клавиатур теперь принимают результаты сервиса каталога. `app/catalog.py` используется только для первоначального импорта, не является источником runtime-данных.

## Быстрый запуск Python

Нужны Python 3.11+ и PostgreSQL. Для frontend — Node.js 22.12+ и pnpm (версия зафиксирована в `frontend/package.json`).

```sh
python -m venv .venv
# Windows: .venv\Scripts\Activate.ps1
# Linux/macOS: source .venv/bin/activate
python -m pip install -r requirements.txt
```

Добавьте настройки из `.env.example` в свой `.env`, сохранив существующий `API_BOT`. Не публикуйте `.env` и токен. `DATABASE_URL` должен указывать на PostgreSQL через драйвер `postgresql+asyncpg`.

```sh
python -m alembic upgrade head
python -m app.db.seed
python -m app.ordering.seed
```

Начальный импорт сохраняет CaVa, Порт-Брю и все четыре существующих напитка с прежними ценами. Повторный импорт не создаёт дублей и не перезаписывает отредактированные цены. Запускайте импорт одним процессом до запуска приложений.

Создайте реальные временные слоты, указав подходящую **будущую** дату. Дата без смещения трактуется в часовом поясе кофейни:

```sh
python -m app.db.manage add-slots --cafe-id 1 --start "2026-11-15T10:00:00+07:00" --count 24 --interval 15 --capacity 5
```

Повтор команды пропускает уже существующие слоты, сохраняя их вместимость. Рабочие часы и вместимость определяются кофейней; приложение не генерирует фиктивное расписание автоматически.

В независимых терминалах:

```sh
# Бот; прежняя команда поддерживается
python main.py
# Также: python -m app.bot.main

# API
python -m uvicorn app.api.main:create_app --factory --host 127.0.0.1 --port 8000 --no-access-log
```

```sh
cd frontend
corepack enable
pnpm install --frozen-lockfile
pnpm dev
```

Для frontend скопируйте `frontend/.env.example` в `frontend/.env` и установите `VITE_API_URL`. Это адрес, доступный **браузеру пользователя**, а не внутреннее имя контейнера. Для проверки API доступны `/docs` и `/health`; бизнес-endpoints требуют Telegram initData.

## Telegram Mini App

1. Опубликуйте frontend и API на HTTPS-адресах.
2. Укажите публичный адрес frontend в `MINI_APP_URL` и его origin в `CORS_ORIGINS`. Перезапустите бот и API.
3. При необходимости настройте кнопку меню / Main Mini App через BotFather. `/start` также показывает отдельную кнопку Mini App, сохраняя обычные кнопки кофеен.
4. Откройте Mini App из личного диалога с ботом. В обычном браузере отображается инструкция открытия через Telegram.

Frontend передаёт исходную `Telegram.WebApp.initData` в `Authorization: tma <initData>`. API проверяет HMAC-SHA256 по [алгоритму Telegram](https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app), подпись сравнивается через `compare_digest`. Проверяется `auth_date`: максимальный возраст задаёт `INIT_DATA_MAX_AGE_SECONDS` (по умолчанию час), допустимое опережение часов — 30 секунд. После истечения срока Mini App нужно открыть заново.

`initDataUnsafe` и переданный клиентом `user_id` не используются для авторизации. Владелец заказа определяется проверенными Telegram-данными и проверяется в сервисном слое. Не логируйте заголовок Authorization и initData; используйте синхронизированные часы на сервере. В production разрешайте только конкретные origins.

## Функции полного бота и Mini App

Исходник — ветка `main`, коммит `ef9595f0783a3753fa8ed4ac9afe90f62ad144d4`.
Из `stud_app` и `codex/backup-local-main` переносить дополнительные функции не требовалось: там ранний выбор кофейни и напитка.

- Роли: студент, назначенный бариста, администратор. Telegram ID виден на главном экране и через `/myid`.
- Оформление в том же порядке: кофейня → раздел → напиток → объём → молоко → пожелания → подтверждение.
- Полное меню CaVa из `main` (38 позиций) и существующее меню Порт-Брю; цены и варианты приходят с сервера.
- Пожелания до 300 символов, отмена черновика, сохранение состояния после перезапуска.
- Избранное до 30 вариантов с удалением и страницами; повтор заказа с актуальной ценой и прежним комментарием.
- История со статусами, оценки 1–5 после выдачи, изменение оценки без второго голоса.
- Панель баристы: очередь и архив, фильтры/страницы, новый → готовится → готов → выдан, отмена до выдачи, закрепление за сотрудником.
- Пауза приёма кофейни, стоп-лист, текущие и будущие периоды, лимиты 0–999, добавление +1/+5 с проверкой ревизии.
- Администратор: сводка статусов, доступ к точкам, назначения и снятие барист; средний рейтинг и сотрудники точки.
- Уведомления о новых заказах и изменении статуса отправляются после commit теми же функциями, что и в боте.
- Блокировки и проверки владельца/рабочих прав применяются на сервере к каждому действию.

Сервисы `app/ordering` перенесены из `main`; обработчики Telegram находятся в `app/bot/flows`, HTTP-адаптер — `app/api/routers/flow.py`. В интерфейсах нет собственных правил цены, резерва или переходов статусов.

Один заказ — один вариант напитка, как в полном боте. При открытии подтверждения место резервируется на 120 секунд и не дольше закрытия приёма. Комментарий не продлевает резерв. Свободно = лимит − принятые заказы − действующие резервы. Отмена освобождает квоту, выдача не освобождает. Повторное подтверждение возвращает тот же номер. Загрузка, проверка и сохранение состояния защищены общей транзакционной advisory-блокировкой PostgreSQL для бота и API. Это простой подход для текущего небольшого проекта; при росте истории нужно заменить загрузку состояния адресными запросами.

Расписание и режим задаются в `app/ordering/settings.py`, расписание рассчитывает перенесённый `app/ordering/schedule.py` по Новосибирску. По умолчанию включены паузы за пять минут до короткого перерыва и до его окончания. Выдача — по готовности, а не по произвольно выбранному времени. Оплата не подключена, как и в исходном боте.

Для рабочих прав создайте `app/local_settings.py` по `app/local_settings.example.py` и задайте ID **своего аккаунта**, показанный в Mini App. Файл исключён из Git. Права не выдаются самому себе кнопкой. При изменении локальных настроек перезапустите приложение. Изменения назначений через администратора сохраняются в PostgreSQL. Сотрудник должен сам начать диалог с ботом для получения уведомлений.

## Данные и совместимость

Миграция `48bbf2db8a9b` добавляет общие таблицы полного сценария с префиксом `flow_`. Они используют ту же БД, фабрику async-сессий и SQLAlchemy Base. Оба актуальных интерфейса читают/меняют одни записи через один `PostgresStore`.

Таблицы ранней версии не удалены. Старые заказы доступны в Mini App через «Мои заказы → Заказы ранней версии» и через GET `/orders`. Старое создание/расчёт `/orders` отключено ответом 410: все новые заказы должны проходить через `/flow/action`, чтобы не возникало отдельной очереди вне панели баристы. Старые Telegram-кнопки оформления обновляются через `/start`.

Launcher применяет миграции и выполняет `python -m app.ordering.seed`. Начальное заполнение не перезаписывает состояния приёма кофеен. Каталог полного бота остаётся в `app/ordering/catalog.py`, как в `main`; новую кофейню и её меню добавляют туда, затем запускают seed. Отдельные обработчики и экраны для новой точки не нужны. Старый `app.db.manage` относится к данным ранней версии и не управляет меню полного сценария.

## Проверки

```sh
python -m pip install -r requirements-dev.txt
python -m pytest -q
cd frontend
pnpm build
```

Большинство интеграционных тестов используют временную SQLite с включёнными внешними ключами. SQLite не заменяет проверку конкуренции на PostgreSQL.

Для конкурентных тестов задайте `TEST_DATABASE_URL=postgresql+asyncpg://.../cofmart_test` и запустите `python -m pytest -q -m postgres`. Тесты создают и удаляют собственные случайные схемы; пользователь БД должен иметь право CREATE SCHEMA. Проверяются независимые пулы подключений бота/API, гонка за последнее место и одновременные повторы одного заказа при разной вместимости.

Изменения схемы: обновите `app/db/models.py`, создайте `python -m alembic revision --autogenerate -m description`, проверьте миграцию и примените `python -m alembic upgrade head`. Не используйте `create_all` при запуске production-приложений.
