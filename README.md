# Cofmart — учебный бот предзаказа кофе

Для запуска нужны Python и работающая PostgreSQL. В окружении conda `cofmart`
установите зависимости, заполните `.env` по `.env.example`, примените миграции:

```powershell
conda activate cofmart
python -m pip install -r requirements.txt
python -m alembic upgrade head
python main.py
```

В PowerShell из корня проекта можно явно выбрать виртуальное окружение:

```powershell
.\.venv\Scripts\python.exe main.py
```

В VS Code выберите конфигурацию «Cofmart: запустить бота» и нажмите F5.
Запускается `main.py`, независимо от открытой вкладки. Файлы внутри `app/`
подключаются через импорты; запускать `app/schedule.py` отдельно не требуется.
`app` — папка этого проекта, устанавливать пакет с таким именем через pip не нужно.

## Что работает

`/start` → выбор роли. Роль «Студент» или команда `/student` → кофейня → раздел меню → напиток → объём →
молоко (для молочных напитков) → подтверждение тестового заказа.
Заказ относится к текущему периоду приёма, напиток выдают по готовности.
`/schedule` показывает паузы приёма и текущий режим. Сам бот работает постоянно.
«Отменить» удаляет текущий черновик. Повторное подтверждение одной кнопкой
возвращает тот же номер заказа.

Перед подтверждением можно нажать «Добавить / изменить комментарий» и написать
пожелание, например «американо со льдом». Комментарий необязателен, ограничен
300 символами, показывается в карточке и сохраняется в заказе. Кнопка «Оставить
как есть» возвращает к подтверждению. Комментарий не меняет цену напитка;
время приёма проверяется и после ввода пожелания.

Пользователи, заказы и комментарии, оценки, избранное, лимиты и резервы слотов,
паузы кофеен, стоп-лист и назначения баристов сохраняются в PostgreSQL.
Перезапуск не удаляет историю. Черновик можно продолжить, пока не истекли
его резерв и окно приёма. Подтверждённые заказы появляются в панели баристы,
сотрудники получают уведомления.
Учитываются слоты приготовления на период приёма и стоп-лист напитков.
Остатки отдельных ингредиентов пока не учитываются.

## PostgreSQL

Рабочее окружение — conda `cofmart`. В `.env` добавляются `DB_HOST`, `DB_PORT`,
`DB_NAME`, `DB_USER`, `DB_PASSWORD`; пример без секретов находится в `.env.example`.
Адрес собирается через `URL.create`, поэтому символы `@`, `:` и `%` в пароле
не нужно вручную кодировать. `.env` исключён из Git.

Команды выполняются из корня проекта:

```powershell
conda activate cofmart
python -m pip install -r requirements.txt
python -m alembic upgrade head
python -m app.db.check
python -m app.db.seed
python -m alembic check
```

- `upgrade head` применяет недостающие миграции. Уже применённая первая миграция
  `c3188f4ff1d8` повторно таблицы не создаёт.
- `app.db.check` проверяет подключение, наличие таблиц и версию миграции.
- `app.db.seed` добавляет CaVa и «Порт-Брю», если их ещё нет. Существующие названия
  и флаг `accepts_orders` сохраняются; повторный запуск не создаёт дубликаты.
- `alembic check` проверяет соответствие реальной схемы моделям.

Модели находятся в `app/db/model.py`. Таблицы:

| Таблица | Что хранится |
| --- | --- |
| `users` | Telegram ID, имя, username и время регистрации |
| `cafes` | Кофейни и разрешение приёма заказов |
| `orders` | Номер, владелец, кофейня, статус, бариста, оценка и снимок заказа |
| `order_drafts` | Черновики с ограниченным по времени резервом |
| `slot_limits` | Лимит и ревизия для каждой кофейни и периода приёма |
| `favorites` | Избранные варианты напитков |
| `barista_overrides` | Назначения и снятие доступа через команды |
| `stopped_products` | Стоп-лист кофеен |
| `order_sessions` | Текущий выбор, ожидание комментария и ввода лимита |
| `message_deletions` | Очередь удаления временных сообщений отдельно для каждого бота |

При обращении в личном чате бот регистрирует автора действия и обновляет имя и
username. Администраторы задаются в локальных настройках. Назначения баристов из
команд имеют приоритет над `BARISTA_CAFES`, в том числе сохранённое снятие доступа.

Обработчики используют `await orders.prepare(...)` и другие сервисы из
`app/services/persistent.py`. Сами правила находятся в `app/services/`, а
`app/db/store.py` загружает состояние, выполняет правило и сохраняет изменённые
строки в одной транзакции. Асинхронные сессии создаются через `session_factory`.
Проверка и бронирование слота защищены транзакционной блокировкой PostgreSQL;
повторное подтверждение не создаёт второй заказ. Номер выдаёт последовательность
PostgreSQL, поэтому пропуски в номерах допустимы. Уведомления отправляются после commit.

Это реализация для небольшого учебного бота: операции заказов пока загружают историю
в память на время транзакции. При росте числа заказов нужны адресные SQL-выборки
и пагинация истории. Меню и цены пока задаются в `app/catalog.py`.
При недоступной базе бот не переходит на временное хранение в памяти.

## Повтор, избранное и оценки

- **Повторить прошлый заказ:** кнопка в меню или `/repeat`. В карточке любого своего
  заказа также есть «Повторить этот заказ». Кофейня, объём, молоко и комментарий
  переносятся в новое оформление. Цена берётся из текущего меню; период приёма,
  наличие и свободный слот проверяются заново. Заказ создаётся только после
  нового подтверждения. Старые цена, номер и период приёма не копируются.
- **Избранное:** `/favorites` или кнопка «Избранные напитки». Напиток можно сохранить
  из черновика или карточки своего заказа. Сохраняются кофейня, объём и молоко;
  одинаковый вариант не дублируется. В списке можно открыть напиток, заказать
  по актуальной цене или удалить. Комментарий прошлого заказа в избранное не переносится.
  Лимит — 30 вариантов на пользователя; список разбит на страницы.
- **Оценка:** после статуса «Выдан» студент получает кнопки 1–5 ⭐. Оценить может
  только владелец заказа. Оценку можно изменить: это по-прежнему один голос.
  Бариста и администратор видят среднюю оценку и число оценённых заказов своей точки.

Избранное и оценки сохраняются после перезапуска. Настройки конкретных аккаунтов лежат отдельно
в локальном файле и не публикуются вместе с исходным кодом.

## Роли и первый запуск панели баристы

### Назначение рабочих ролей

Работа идёт в личном чате с ботом. Команды доступны в меню Telegram:

| Команда | Назначение |
| --- | --- |
| `/start`, `/roles` | Выбор доступной роли |
| `/student` | Вход в оформление заказа |
| `/myorders` | Последние пять своих заказов, комментарии и текущие статусы |
| `/favorites` | Избранные варианты напитков |
| `/repeat` | Карточка последнего заказа для повторения |
| `/barista` | Рабочие кофейни сотрудника |
| `/admin` | Статистика точек и назначение барист |
| `/myid` | Telegram ID для настройки доступа |

1. Запустите бота, напишите `/myid` со своего аккаунта.
   Нужен ID **вашего аккаунта**, а не ID бота из BotFather или начала токена.
2. Скопируйте `app/local_settings.example.py` в `app/local_settings.py` и добавьте
   полученный ID в локальный файл, например:

   ```python
   ADMIN_IDS = {123456789}  # замените на свой ID
   BARISTA_CAFES = {
       234567890: {"1"},       # CaVa
       345678901: {"2"},       # Порт-Брю
       456789012: {"1", "2"}, # доступ к обеим точкам
   }
   ```

3. Перезапустите `main.py`. `/start` покажет доступные рабочие роли.
4. Каждый сотрудник должен сам открыть бота и нажать `/start`, чтобы бот мог
   отправлять ему уведомления.

Администратор может работать с обеими точками, назначать и снимать доступ:

```text
/grant_barista 234567890 1
/revoke_barista 234567890 1
```

Изменения доступа через команды сохраняются в PostgreSQL. `BARISTA_CAFES` задаёт
начальные назначения, пока они не переопределены командами. Администраторы
назначаются только через `ADMIN_IDS`. `app/local_settings.py` исключён из Git.
Без начальных назначений и записей в базе рабочий доступ не предоставляется; выбрать роль и получить права
самостоятельно нельзя. Права проверяются при каждом действии, включая старые кнопки.

## Работа баристы

Выберите свою точку в `/barista`. На экране доступны:

- Очередь с фильтрами «Новые», «Готовятся», «Готовы», обновлением и страницами.
- Карточка заказа: напиток, объём, молоко, пожелания, сумма, время выдачи и ответственный бариста.
- Статусы: **новый → готовится → готов → выдан**. При взятии в работу заказ
  закрепляется за сотрудником; дальше менять его может этот сотрудник или администратор.
- Отмена до выдачи. Выданные и отменённые заказы остаются в архиве.
- Пауза онлайн-приёма своей кофейни. Уже принятые заказы продолжают обслуживаться.
- Наличие напитков: выключение позиции скрывает все её объёмы/варианты молока.
  Доступность проверяется повторно при подтверждении студентом.

### Слоты приёма

В `/barista` выберите кофейню → «Слоты приёма» → нужный период приёма.
Можно нажать готовое число или «Ввести число» и отправить целый лимит от 0 до 999.
Кнопки **«+1 слот»** и **«+5 слотов»** увеличивают общий лимит и свободный остаток.
Они доступны баристам своей точки и администраторам; студент не может добавить слоты
даже через подделанную кнопку. Повторное нажатие старой кнопки пополнения отклоняется.
Квота задаётся отдельно для каждой кофейни и каждого периода между паузами;
по умолчанию — 10. Доступны текущий и будущие периоды сегодня и завтра.
Период после 17:10 продолжается до 09:40 следующего дня: в полночь квота
автоматически не пополняется. После короткого перерыва начинается новый период
со своим настроенным лимитом, либо с лимитом по умолчанию.

Студент видит остаток текущего периода на кнопке кофейни, например
«свободно 7/10». Кнопка «Обновить слоты» обновляет остатки; ранее отправленные
карточки не меняются автоматически.

Один заказ занимает один слот. При показе подтверждения слот резервируется на
120 секунд, но не дольше времени закрытия приёма. Комментарий не продлевает резерв.
До подтверждения можно отказаться от оформления; резерв освободится сразу.
Истёкшие резервы исключаются при следующей проверке доступности.

Свободно = лимит − принятые заказы − действующие резервы. Подтверждение превращает
резерв в один заказ; повторное нажатие не занимает второй слот. Отмена принятого
заказа баристой освобождает слот. Выдача **не** освобождает его: напиток уже использовал
производственную квоту этого периода.

Пример: было 10 свободных → заказ подтверждён → осталось 9 → напиток выдан →
по-прежнему 9. Если бариста добавит 1 слот, свободных станет 10 при общем лимите 11.
Слот расходуется один раз. В панели отдельно показаны заказы в работе, выданные
заказы (потраченная квота), временные резервы и свободные слоты.

Лимит нельзя уменьшить ниже числа принятых заказов и действующих резервов.
При одновременном редактировании двумя сотрудниками устаревшее изменение отклоняется.
Нулевой лимит останавливает новые заказы на конкретный период.

В тестовом режиме используется одна тестовая перемена на локальную дату. В полночь
начинается новая квота; старый черновик подтвердить нельзя. Начальный лимит и время
резерва задаются `DEFAULT_SLOTS_PER_BREAK` и `SLOT_RESERVATION_SECONDS` в `app/settings.py`.
Лимиты и резервы сохраняются в PostgreSQL. После перезапуска остаток учитывает
сохранённые заказы и ещё действующие резервы.

Новые заказы рассылаются назначенным баристам точки и администраторам. При изменении
статуса студент получает уведомление; при готовности — приглашение забрать напиток.
Повторное подтверждение заказа не создаёт повторной рассылки. Устаревшие кнопки
статуса отклоняются, поэтому два сотрудника не могут одновременно взять один заказ.
Кнопки содержат номер и случайный ключ заказа. Сохранённый заказ остаётся доступным
по своей кнопке после перезапуска. При возврате к выбору напитка
старый черновик и ожидание комментария закрываются.
Если пользователь заблокировал бота, ошибка уведомления пишется в журнал, а заказ
остаётся доступным в очереди/истории. Автоматических повторов доставки пока нет.

Это тестовый процесс без оплаты. «Приём открыт» означает разрешение со стороны
кофейни; при `FOLLOW_SCHEDULE = True` дополнительно действуют короткие паузы приёма.
Паузы, стоп-лист, статусы и назначения из команд сохраняются в PostgreSQL.

При запуске проверяются типы настроек ролей. Если в них ошибочно указан ID самого
бота, в консоли появляется предупреждение. Временный сбой обновления меню команд
не мешает начать приём сообщений. При остановке HTTP-сессия бота закрывается.

## Удаление служебных сообщений

Подтверждение заказа, отмена, ошибки, подсказки и короткие подтверждения действий
удаляются примерно через **60 секунд**. Уведомления студенту и баристе о новом
заказе или смене статуса — через **5 минут**. Очередь проверяется каждые 5 секунд.
Всплывающие ответы на кнопки исчезают средствами Telegram.

Главное меню, история, рабочие панели и черновик с кнопкой подтверждения остаются
доступны. Если открыть временное уведомление как рабочую карточку заказа, её
прежний таймер отменяется. Удаление сообщения не удаляет сам заказ: его можно
снова открыть через `/myorders` или панель баристы; оценить — из карточки своего заказа.

Время для новых сообщений задаётся в `app/settings.py`:

```python
SERVICE_MESSAGE_TTL_SECONDS = 60
NOTIFICATION_TTL_SECONDS = 300
```

`0` отключает планирование удаления новых сообщений соответствующего типа.
После изменения настроек перезапустите бота. Уже запланированные задачи
хранятся в PostgreSQL и выполнятся после перезапуска. Токен и пароль в очереди
не хранятся — только ID бота, чата, сообщения и время удаления.

При сетевой ошибке удаление откладывается. Если Telegram запрещает удалить
сообщение, это записывается в журнал. Например, Bot API ограничивает удаление
сообщений возрастом 48 часов: после длительного простоя некоторые старые
сообщения могут остаться. [Ограничения Telegram](https://core.telegram.org/bots/api#deletemessage).

## Тестовый режим

В `app/settings.py` установлен переключатель:

```python
FOLLOW_SCHEDULE = True
```

`True` — обычный режим: новые заказы принимаются постоянно, кроме пауз перед
короткими перерывами и во время них. Ручная пауза кофейни и свободные слоты
проверяются отдельно. `False` отключает паузы для тестирования: используется
одна тестовая квота на локальную дату, а резерв ограничен концом этой даты.
Резерв в обоих режимах действует не более 120 секунд. После изменения
перезапустите бота. Меню, история и рабочая панель доступны в обоих режимах
и во время пауз; ограничения относятся к созданию и подтверждению новых заказов.

## Меню CaVa

В `app/catalog.py` внесены 38 позиций с фотографии: кофе, авторские напитки,
чай и другие напитки. Вкусы и виды чая вынесены в отдельные позиции.
У каждой позиции есть варианты объёма и цены; для молочных напитков можно
выбрать альтернативное молоко с доплатой 70 ₽.

Для чая, глинтвейна, смузи и милкшейка объём на фотографии не читается:
временно показано «порция». Значения можно уточнить в `PRODUCTS`.
Учебные цены «Порт-Брю» сохранены. Пустые клетки на фотографии не превращены
в варианты заказа.

Меню хранится в одном словаре `PRODUCTS`. Функция `get_drink(cafe_id, sku)`
проверяет выбранный объём и молоко, затем возвращает название и итоговую цену.
Например, `4_350` — латте 350 мл, `4_350a` — тот же напиток на альтернативном
молоке. Обработчики и оформление заказа используют эту функцию, поэтому
отдельные таблицы названий и цен поддерживать не требуется.

## Правила времени

Время — Новосибирск (UTC+7). Пять пар ежедневно с 09:00: первая половина
45 минут, короткий перерыв 5 минут, вторая половина 45 минут, затем
15 минут между парами. После последней пары межпарного перерыва нет.
Выходные, праздники и изменения расписания пока не учитываются.

| Пара | Начало | Короткий перерыв | Перерыв после пары |
| --- | --- | --- | --- |
| 1 | 09:00 | 09:45–09:50 | 10:35–10:50 |
| 2 | 10:50 | 11:35–11:40 | 12:25–12:40 |
| 3 | 12:40 | 13:25–13:30 | 14:15–14:30 |
| 4 | 14:30 | 15:15–15:20 | 16:05–16:20 |
| 5 | 16:20 | 17:05–17:10 | — |

Приём новых заказов приостанавливается **ровно за пять минут до короткого
перерыва** и возобновляется **после его окончания**:

| Пара | Пауза приёма |
| --- | --- |
| 1 | 09:40–09:50 |
| 2 | 11:30–11:40 |
| 3 | 13:20–13:30 |
| 4 | 15:10–15:20 |
| 5 | 17:00–17:10 |

В 09:40 уже нельзя создать или подтвердить новый заказ; в 09:50 снова можно.
На длинных переменах, до начала пар и вечером приём открыт, если кофейня
разрешила его и есть слоты. Бот продолжает показывать меню и историю и позволяет
баристе обслуживать уже принятые заказы во время любой паузы.

Сервер проверяет время при создании черновика и подтверждении, повторно получая
текущее время после ожидания блокировки PostgreSQL. Резерв заканчивается не позже
начала паузы. Квота вечера и следующей ночи общая; действует до следующего 09:40.
Повторное подтверждение уже принятого заказа возвращает тот же заказ и во время
паузы, не создавая новый. Старыми кнопками нельзя обойти время приёма.

## Файлы

- `main.py` — запуск и подключение роутера.
- `app/catalog.py` — кофейни, напитки и цены.
- `app/keyboards.py` — кнопки.
- `app/handlers/student.py` — команды и нажатия.
- `app/schedule.py` — расписание, часовой пояс и окна приёма.
- `app/settings.py` — переключатель `FOLLOW_SCHEDULE`.
- `app/services/orders.py` — проверка и подтверждение тестовых заказов.
- `app/services/roles.py` — проверка прав и назначения сотрудников.
- `app/services/cafes.py` — пауза приёма и стоп-лист.
- `app/services/persistent.py` — асинхронный доступ обработчиков к сервисам.
- `app/db/model.py`, `app/db/store.py` — таблицы и транзакции PostgreSQL.
- `migrations/` — история изменений схемы Alembic.
- `app/handlers/entry.py` — выбор роли и команды входа.
- `app/handlers/staff.py` — рабочая панель баристы и администратора.
- `app/staff_keyboards.py` — кнопки рабочих панелей.
- `app/ui.py` — общие карточки и отображение заказов.
- `app/notifications.py` — уведомления о новых заказах и статусах.
- `app/message_cleanup.py` — таймеры и фоновое удаление временных сообщений.
- `tests/test_message_cleanup.py` — сроки удаления, повторные попытки и остановка worker.
- `tests/test_orders.py` — границы времени, даты и повторные подтверждения.
- `tests/test_bot_flow.py` — сценарий по кнопкам aiogram с заглушками Telegram.
- `tests/test_validation.py` — старые кнопки после перезапуска, сбои карточек,
  конкурентные действия, матрица ролей/статусов и ограничения Telegram.
- `tests/test_startup.py`, `tests/test_routing.py` — запуск, команды и маршрутизация.

Проверки в conda `cofmart`:

```powershell
python -m unittest discover -s tests -v
```

Проверки настоящей PostgreSQL, включая гонки за слот и повторное подтверждение:

```powershell
$env:COFMART_TEST_POSTGRES = "1"
python -m unittest discover -s tests -v
Remove-Item Env:COFMART_TEST_POSTGRES
```

Интеграционные тесты применяют миграции в отдельных временных схемах, затем удаляют
только эти схемы. Рабочая `public` не изменяется. Роли тестового подключения нужно
право создавать схемы. Telegram в тестах подменён, сообщения людям не отправляются.
