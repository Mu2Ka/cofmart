# Cofmart — учебный бот предзаказа кофе

Запуск: установите зависимости `python -m pip install -r requirements.txt`,
добавьте `API_BOT=токен` в `.env`, выполните `python main.py`.

В PowerShell из корня проекта можно явно выбрать виртуальное окружение:

```powershell
.\.venv\Scripts\python.exe main.py
```

В VS Code выберите конфигурацию «Cofmart: запустить бота» и нажмите F5.
Запускается `main.py`, независимо от открытой вкладки. Файлы внутри `app/`
подключаются через импорты; запускать `app/schedule.py` отдельно не требуется.
`app` — папка этого проекта, устанавливать пакет с таким именем через pip не нужно.

## Что работает

`/start` → выбор роли. Роль «Студент» или команда `/student` → кофейня → раздел меню → напиток → объём →
молоко (для молочных напитков) → подтверждение тестового заказа.
При включённом расписании перед подтверждением появляется выбор перерыва.
`/schedule` показывает сегодняшнее расписание и текущий режим.
«Отменить» удаляет текущий черновик. Повторное подтверждение одной кнопкой
возвращает тот же номер заказа.

Перед подтверждением можно нажать «Добавить / изменить комментарий» и написать
пожелание, например «американо со льдом». Комментарий необязателен, ограничен
300 символами, показывается в карточке и сохраняется в заказе. Кнопка «Оставить
как есть» возвращает к подтверждению. Комментарий не меняет цену напитка;
время приёма проверяется и после ввода пожелания.

База данных и оплата пока не подключены. Черновики и заказы хранятся в памяти
одного процесса и исчезают при перезапуске. Подтверждённые заказы появляются
в панели баристы, сотрудники получают уведомления.
Лимиты мощности и остатки товаров ещё не учитываются.

## Роли и первый запуск панели баристы

Работа идёт в личном чате с ботом. Команды доступны в меню Telegram:

| Команда | Назначение |
| --- | --- |
| `/start`, `/roles` | Выбор доступной роли |
| `/student` | Вход в оформление заказа |
| `/myorders` | Последние пять своих заказов, комментарии и текущие статусы |
| `/barista` | Рабочие кофейни сотрудника |
| `/admin` | Статистика точек и назначение барист |
| `/myid` | Telegram ID для настройки доступа |

1. Запустите бота, напишите `/myid` со своего аккаунта.
2. Добавьте полученный ID в `app/settings.py`, например:

   ```python
   ADMIN_IDS = {123456789}  # замените на свой ID
   BARISTA_CAFES = {
       234567890: {"1"},       # CaVa
       345678901: {"2"},       # Порт-Брю
       456789012: {"1", "2"}, # доступ к обеим точкам
   }
   ```

3. Перезапустите `main.py`. `/start` покажет доступные рабочие роли.
4. Каждый сотрудник должен сам открыть бота и нажать `/start`, чтобы бот мог
   отправлять ему уведомления.

Администратор может работать с обеими точками, назначать и снимать доступ:

```text
/grant_barista 234567890 1
/revoke_barista 234567890 1
```

Изменения доступа через команды живут до перезапуска. Для постоянного назначения
запишите ID в `BARISTA_CAFES`. Администраторы назначаются только через `ADMIN_IDS`.
Пустые настройки не дают рабочий доступ никому; выбрать роль и получить права
самостоятельно нельзя. Права проверяются при каждом действии, включая старые кнопки.

## Работа баристы

Выберите свою точку в `/barista`. На экране доступны:

- Очередь с фильтрами «Новые», «Готовятся», «Готовы», обновлением и страницами.
- Карточка заказа: напиток, объём, молоко, пожелания, сумма, время выдачи и ответственный бариста.
- Статусы: **новый → готовится → готов → выдан**. При взятии в работу заказ
  закрепляется за сотрудником; дальше менять его может этот сотрудник или администратор.
- Отмена до выдачи. Выданные и отменённые заказы остаются в архиве.
- Пауза онлайн-приёма своей кофейни. Уже принятые заказы продолжают обслуживаться.
- Наличие напитков: выключение позиции скрывает все её объёмы/варианты молока.
  Доступность проверяется повторно при подтверждении студентом.

Новые заказы рассылаются назначенным баристам точки и администраторам. При изменении
статуса студент получает уведомление; при готовности — приглашение забрать напиток.
Повторное подтверждение заказа не создаёт повторной рассылки. Устаревшие кнопки
статуса отклоняются, поэтому два сотрудника не могут одновременно взять один заказ.
Если пользователь заблокировал бота, ошибка уведомления пишется в журнал, а заказ
остаётся доступным в очереди/истории. Автоматических повторов доставки пока нет.

Это тестовый процесс без оплаты. «Приём открыт» означает разрешение со стороны
кофейни; при `FOLLOW_SCHEDULE = True` дополнительно действуют временные окна.
Паузы, стоп-лист, статусы и назначения из команд хранятся в памяти одного процесса.

## Тестовый режим

В `app/settings.py` установлен переключатель:

```python
FOLLOW_SCHEDULE = False
```

`False` — тестовые заказы доступны в любое время, выбор перерыва и дедлайн
пропускаются. `True` — действуют окна приёма, описанные ниже. После изменения
перезапустите бота. Проверка пользователя, устаревших кнопок, цены и повторного
подтверждения работает в обоих режимах.

## Меню CaVa

В `app/catalog.py` внесены 38 позиций с фотографии: кофе, авторские напитки,
чай и другие напитки. Вкусы и виды чая вынесены в отдельные позиции.
У каждой позиции есть варианты объёма и цены; для молочных напитков можно
выбрать альтернативное молоко с доплатой 70 ₽.

Для чая, глинтвейна, смузи и милкшейка объём на фотографии не читается:
временно показано «порция». Значения можно уточнить в `PRODUCTS`.
Учебные цены «Порт-Брю» сохранены. Пустые клетки на фотографии не превращены
в варианты заказа.

Меню хранится в одном словаре `PRODUCTS`. Функция `get_drink(cafe_id, sku)`
проверяет выбранный объём и молоко, затем возвращает название и итоговую цену.
Например, `4_350` — латте 350 мл, `4_350a` — тот же напиток на альтернативном
молоке. Обработчики и оформление заказа используют эту функцию, поэтому
отдельные таблицы названий и цен поддерживать не требуется.

## Правила времени

Время — Новосибирск (UTC+7). Пять пар ежедневно с 09:00: первая половина
45 минут, короткий перерыв 5 минут, вторая половина 45 минут, затем
15 минут между парами. После последней пары межпарного перерыва нет.
Выходные, праздники и изменения расписания пока не учитываются.

| Пара | Начало | Короткий перерыв | Перерыв после пары |
| --- | --- | --- | --- |
| 1 | 09:00 | 09:45–09:50 | 10:35–10:50 |
| 2 | 10:50 | 11:35–11:40 | 12:25–12:40 |
| 3 | 12:40 | 13:25–13:30 | 14:15–14:30 |
| 4 | 14:30 | 15:15–15:20 | 16:05–16:20 |
| 5 | 16:20 | 17:05–17:10 | — |

Приём открывается в начале соответствующей половины пары и закрывается
**ровно за пять минут до перерыва**. Например, первый заказ можно подтвердить
с 09:00 включительно до 09:40, не включая 09:40. Следующее окно —
09:50–10:30. Во время перерыва и до начала дня приём закрыт.
Заказ на будущую половину заранее оформить нельзя. Если окон больше нет,
бот показывает время открытия на следующий день.

Сервер заново проверяет дедлайн при выборе перерыва и при подтверждении.
Кнопка со вчерашним перерывом или отменённым черновиком не создаст заказ.

## Файлы

- `main.py` — запуск и подключение роутера.
- `app/catalog.py` — кофейни, напитки и цены.
- `app/keyboards.py` — кнопки.
- `app/handlers/student.py` — команды и нажатия.
- `app/schedule.py` — расписание, часовой пояс и окна приёма.
- `app/settings.py` — переключатель `FOLLOW_SCHEDULE`.
- `app/services/orders.py` — проверка и подтверждение тестовых заказов.
- `app/services/roles.py` — проверка прав и назначения сотрудников.
- `app/services/cafes.py` — пауза приёма и стоп-лист.
- `app/handlers/entry.py` — выбор роли и команды входа.
- `app/handlers/staff.py` — рабочая панель баристы и администратора.
- `app/staff_keyboards.py` — кнопки рабочих панелей.
- `app/ui.py` — общие карточки и отображение заказов.
- `app/notifications.py` — уведомления о новых заказах и статусах.
- `tests/test_orders.py` — границы времени, даты и повторные подтверждения.
- `tests/test_bot_flow.py` — сценарий по кнопкам aiogram с заглушками Telegram.

Проверки из виртуального окружения: `.\.venv\Scripts\python.exe -m unittest discover -s tests -v`.
